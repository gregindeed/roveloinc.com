Narrow select('*') on the hot list queries

recommended medium effort

Same pattern on [year]/page.tsx and account/page.tsx. Narrowing the highest-traffic list queries to the columns actually used trims the payload and the DB work on every dashboard load. Medium risk (must include every field the code reads), so worth doing deliberately rather than blindly — I left it for you rather than guessing the column set.

Middleware runs ~2 auth round-trips per navigation

recommended low priority

Every /admin and /portal request hits supabase.auth.getUser() in middleware (a network validation), and /admin also runs an extra profiles.select('role') — then the page render calls getViewer(), which fetches user + profile + memberships again (it's cached per-render, but middleware is a separate request context, so the role query happens twice). This is the "laggy navigation" your own getViewer comment mentions. Fully removing it is fiddly (session refresh needs the middleware call), but the redundant role lookup could move into a JWT claim or a short-lived cookie later. Noting, not urgent.
